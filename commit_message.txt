🔒 Fix hardcoded JWT Key

🎯 What: Removed the hardcoded fallback JWT secret key in Program.cs.
⚠️ Risk: If the configuration for `Jwt:Key` is missing, the application would silently use a known, publicly available string (`UmaChaveSuperSecretaMuitoLongaParaOJWT12345!`) to sign and verify JWT tokens. An attacker who knows or discovers this hardcoded key could forge valid JWT tokens, gaining unauthorized access or elevating privileges, potentially compromising the entire application.
🛡️ Solution: Replaced the hardcoded fallback string with a `throw new InvalidOperationException(...)`. This implements a fail-fast mechanism; if the required secure key is not provided via configuration, the application will refuse to start, preventing an insecure deployment.
