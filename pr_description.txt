🔒 Fix Insecure Direct Object Reference (IDOR) on Check-in

🎯 **What:** The vulnerability fixed
The check-in endpoint (`api/mobile/os/{id}/checkin`) previously accepted the `TecnicoId` directly from the request body. This allowed any authenticated user to spoof check-ins for other technicians by simply sending their ID in the payload.

⚠️ **Risk:** The potential impact if left unfixed
An attacker could perform check-ins on behalf of other technicians, compromising the integrity of field visit records and potentially leading to fraudulent activity or incorrect service logs.

🛡️ **Solution:** How the fix addresses the vulnerability
The endpoint now extracts the `TecnicoId` directly from the authenticated user's claims (`ClaimTypes.NameIdentifier`). The `TecnicoId` field has been removed from the `CheckInRequest` model to enforce this server-side validation and prevent user-supplied spoofing.
