🎯 **What:** Removed the hardcoded default demo user password from `Program.cs`.

⚠️ **Risk:** Hardcoding credentials exposes sensitive access to anyone with access to the source code, posing a significant security risk (CWE-798: Use of Hard-coded Credentials). While this is a demo account, hardcoded passwords violate secure configuration practices and could potentially be left intact in production deployments.

🛡️ **Solution:**
- Updated `Program.cs` to read the demo user credentials securely from configuration (`DemoCredentials:Username` and `DemoCredentials:Password`).
- Ensured the demo account is only seeded if a password is explicitly provided via configuration.
- Added a `DemoCredentials` block to `appsettings.json` to make the configuration discoverable.
- Updated `README.md` to instruct users on how to properly set the `DemoCredentials__Password` environment variable to test demo mode via Docker Compose and native execution.
