🧹 [Refactor] Extract PDF generation logic into PdfGeneratorService

🎯 What: Extracted the inline PDF generation logic (using QuestPDF) from the `ImprimirOs` method in `AdminController.cs` into a dedicated `PdfGeneratorService` class. Registered the new service in `Program.cs` and injected it into the controller.

💡 Why: This improves maintainability and readability by keeping the controller focused on handling HTTP requests and returning views/files, while delegating the complex PDF generation logic (which was > 100 lines) to a separate service class. This follows the Single Responsibility Principle (SRP).

✅ Verification: Compiled successfully with `dotnet build AssistenciaTech.sln` and all tests passed using `dotnet test AssistenciaTech.sln`. Refactored files were manually reviewed.

✨ Result: `AdminController.cs` is cleaner and easier to read, and the PDF generation logic is encapsulated in `PdfGeneratorService`, making it reusable and easier to maintain/test in the future.
