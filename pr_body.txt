🎯 **What:** The TelegramNotificationService lacked unit tests to verify its core notification logic and API interactions.

📊 **Coverage:** The following scenarios are now tested:
- Aborting notification early when the client is null.
- Aborting notification when the Telegram Bot Token is missing in configuration.
- Aborting notification when the client has an empty Chat ID.
- Successfully sending a notification with valid parameters (mocking HTTP success).
- Gracefully handling and logging non-success HTTP API responses without throwing exceptions.
- Gracefully handling generic exceptions (e.g. network errors) without throwing.

✨ **Result:** Enhanced code reliability by ensuring the notification service correctly interprets inputs, manages its external dependencies, and suppresses transient errors from surfacing to the main workflow.
